# Локальные правки поверх v1.4.4 (2026-09-04)

Список багов, найденных и исправленных в этой сессии, с воспроизведением на
реальных данных сервера `add-share`. Оригинальный `VERSION` не трогали —
это неофициальный патч-сет, не апстрим-релиз.

## 1. `list_block_devices` — regex-коллизия TYPE=/FSTYPE=
`grep -oP '(?<=TYPE=")[^"]*'` матчился и внутри `FSTYPE="..."` (подстрока
"TYPE=" есть и там). Для любого устройства с непустым FSTYPE это давало
два совпадения вместо одного, `dtype` становился многострочным и не
проходил фильтр `disk/part/lvm/loop` — устройство молча пропадало из
списка. Пофикшено добавлением `\s` перед `TYPE="` в лукбехайнде.
Эффект: вкладка «Диски» показывала только неразмеченные устройства,
все смонтированные диски и loop-ISO были невидимы.

## 2. `disk_smart_summary` — `set -e` рвал цикл на диске без Temperature
`temp="$(... | grep -oP '\d+' | head -1)"` возвращает ненулевой код,
если совпадений нет (NVMe/некоторые SSD без строки Temperature) — под
`set -e -o pipefail` это останавливало вообще весь цикл по дискам,
не только температуру для одного диска. Добавлено `|| true`.

## 3. `disk_smart_summary` — ложный FAILED + мусорная температура
`grep -qi "FAILED"` матчился на заголовок колонки `WHEN_FAILED`,
присутствующий в выводе `smartctl -A` ВСЕГДА, даже у здорового диска —
из-за этого панель показывала «ОТКАЗ, СРОЧНО ЗАМЕНИТЬ» для полностью
исправных дисков. Температура бралась как первое число в строке —
для ATA-атрибутов это ID атрибута (194 для Temperature_Celsius), а не
реальная температура. Исправлено: health match теперь ищет конкретную
фразу `test result: PASSED/FAILED` (как в реальном выводе `smartctl -H`),
температура берётся из конкретного поля (RAW_VALUE, awk $10) с фоллбэком
на NVMe-формат `Temperature: NN Celsius`.

## 4. `list_iso_files` — не показывал статус монтирования
Добавлена проверка `losetup -j` + `lsblk -no MOUNTPOINT` на каждый
найденный `.iso`-файл; формат вывода расширен до
`ISOFILE|path_b64|size|mounted_flag|mountpoint_b64`. Соответствующий
рендер на фронтенде (`templates/index.html`) теперь показывает
«смонтирован в ...» + кнопку «отмонтировать» вместо статичного поля
ввода, если файл уже смонтирован.

## 5. `create_share` — падал без объяснений на read-only ФС
Функция всегда (даже для read-only шар) делает `chown`/`chmod` на путь
шары — физически невозможно на read-only смонтированной ФС (например,
если путь шары совпадает с точкой монтирования ISO). Добавлена
проверка через `findmnt -no OPTIONS` до `chown`/`chmod`, с понятным
сообщением и советом (создать шару на обычном писуемом пути, а ISO
монтировать в подпапку внутри неё), вместо сырого системного
`Read-only file system` или неинформативной обрезанной строки в
аудит-логе.

## 6. `sambapanel.service` — `PrivateTmp=true` ломал ЛЮБОЕ монтирование
Самая серьёзная находка. `PrivateTmp=true` создаёт для сервиса
отдельный mount-namespace (не только для `/tmp`) с приватным
распространением монтирований — из-за этого **любой** `mount`,
сделанный через веб-панель (`mount_iso`, `mount_disk`), был виден
только процессу самой панели и никогда не долетал ни до хоста, ни до
`smbd` (у него свой независимый namespace). Панель показывала
«смонтировано», но по сети через Samba ничего не раздавалось.
`PrivateTmp=true` убран из юнита.

## 7. `create mask = 0664` — на шарах нельзя было запускать .exe
Маска обрезала бит выполнения у ЛЮБОГО файла, попадающего на шару
через запись (загрузка с Windows), независимо от того, что просил
клиент. Windows отказывался запускать `.exe`, скопированные на шару,
из-за отсутствия Unix x-бита. Изменено на `create mask = 0777`.
Не влияет на ISO-шары (read-only, туда ничего не пишется).
**Важно**: касается только НОВЫХ файлов; уже лежащие на шарах `.exe`
нужно поправить вручную (`chmod +x` или пересобрать шару).

## Не исправлено (обсуждалось, решение отложено)
- `audit_log()` в `app.py` обрезает вывод хелпера до первой строки —
  мешает диагностике через журнал действий.
- Кнопка «создать шару» не блокируется на время запроса — повторные
  клики шлют дублирующие `create_share`.
